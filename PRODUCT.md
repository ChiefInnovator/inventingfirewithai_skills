# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Developers using Codex, Claude Code, or GitHub Copilot who need focused reusable
instructions and bundled helpers. Maintainers need to change and verify the
library without losing host-specific behavior or private user data boundaries.

## Product Purpose

Help visitors select, install, and understand five reusable skills: Pragmatic
Coder, Slam, MCP Picker, Travel Like a Local, and Figma-to-Flutter. Success means
finding the matching complete client package, knowing when to invoke it, and
understanding what its checks actually establish.

## Positioning

Compact entrypoints link to task-specific resources rather than preload an
overlapping library of instructions. Three matching client packages preserve
native invocation, hooks, metadata, and available tool boundaries.

## Operating Context

Packages live under `skills/{codex,claude,copilot}`. GitHub hosts source, pull
requests, checks, and editorial evaluations. Feature branches merge into develop;
develop alone promotes to main. GitHub Pages publishes the static `main:/docs`
site with Jekyll. Local and CI checks support evidence-bounded maintenance.

## Capabilities and Constraints

- Keep the existing five families, static HTML/CSS/JavaScript, Jekyll documentation,
  bundled resources, and complete-folder distribution.
- Record source delivery, CI, deployment, and live host acceptance separately.
- Preserve generic packages: personal profiles, trip state, secrets, customer
  assumptions, and machine-specific paths do not belong in distributed skills.
- Cloud Copilot repository rules target develop, including drafts and new pushes.
  Account-level preferences are separate and are not changed by site work.
- Design workflows use Google's EGM and Impeccable. They are maintainer tools,
  not additions to the five downloadable skill families.
- No new service, authentication, telemetry, framework, theme switch, or automatic
  private-storage/booking implementation is part of this work.

## Brand Commitments

Preserve Inventing Fire with AI, the checked-in layered fire mark, compact
first-viewport branding, Chivo typography, and the existing dark author panel with
its limited Fraunces byline. Preserve the factual Rich Crane/MILL5/Microsoft MVP
attribution and current links. Keep the voice direct, practical, and specific.

## Evidence on Hand

The repository contains source packages, Python regression tests, fictional travel
smoke fixtures, an editorial scorecard, and a complete travel source ZIP. Editorial
scores are not comparative model benchmarks. Live cross-host storage, booking,
assistive-technology acceptance, search indexing, and AI citations need separate
evidence; do not infer them from structural checks.

## Product Principles

1. Make the next action clear: select a skill, select a client, install the whole folder.
2. Preserve client behavior while keeping shared resources aligned.
3. Prefer factual, crawlable content and bounded claims over promotional proof.
4. Expose verification limits and usable fallback links.
5. Preserve focused scope, private data boundaries, and protected-branch delivery.

## Accessibility & Inclusion

Use native semantics, accurate ARIA names/states, keyboard entry and visible
focus, descriptive links and image alternatives, readable contrast and spacing,
and layouts that work at phone, intermediate, and desktop widths. Supplement
static regressions with rendered checks and report untested assistive technology.
